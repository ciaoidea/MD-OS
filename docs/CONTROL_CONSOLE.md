# MD-OS Control Console

The Control Console is an experimental second entrypoint for MD-OS.

It does not replace the development launcher:

```text
./bootstrap-md-os-codex.sh
  -> Codex operates MD-OS for repository development

mdos-console
  -> MD-OS executes preauthorized native commands directly
  -> MD-OS invokes Codex as a read-only typed proposal engine for natural language
```

## Prerequisites

- Node.js 20 or newer
- Codex CLI installed and authenticated
- this repository available locally

Verify Codex first:

```bash
codex --version
```

## Start

After installing the command as described below, start it with `mdos-console`.
Equivalent repository-local commands are:

```bash
node md-os/os/mdos.js console start
npm run console
```

## Install The Shell Command

To make this exact MD-OS workspace available as an agentic shell from
any directory, install its user-local launcher:

```bash
./install-md-os-console.sh
```

Then, from any directory:

```bash
mdos-console
```

The installer links the `mdos-console` runtime directly under `${XDG_BIN_HOME}`
or `$HOME/.local/bin`; it does not route through a bootstrap script and refuses
to overwrite an existing command. Remove only the symlink owned by this
workspace with:

```bash
./install-md-os-console.sh --uninstall
```

Alternatively, install the whole package into the npm global command prefix:

```bash
npm install --global .
```

The package-level console can then be started from an MD-OS workspace with
either command:

```bash
mdos console start
mdos-console
```

The global command supplies the runtime; the active workspace still supplies
`AGENTS.md`, the `md-os/` operating boundary, state, policies, registry, and
private local history.

By default the console binds to:

```text
http://127.0.0.1:4937/
```

Choose another local port or prevent automatic browser opening:

```bash
mdos-console --port 4938 --no-open
```

Choose an explicit Codex model only when required:

```bash
mdos-console --model <available-codex-model>
```

Human input is the shared native-command and natural-language shell surface.
By default it is appended to the private, Git-ignored equivalent of
`.bash_history`:

```text
md-os/ops/local/control-console/history.ndjson
```

Save the complete local session transcript only when explicitly wanted, or
disable all console history:

```bash
mdos-console --save-chat
mdos-console --no-history
```

Session ledgers live under `md-os/ops/local/control-console/sessions/`. Neither
command history nor a transcript becomes canonical MD-OS memory without a
separate verified promotion.

No quotes or apostrophes are required. The Console distinguishes machine
syntax from natural language before it calls a model.

## Native Commands: Cortex-Style Bypass

Type a preauthorized native command exactly as in a terminal:

```text
ls
ls -la
pwd
cd kb
ps aux
top
whoami
id
uname -a
uptime
free -h
```

These commands do not go to Codex:

```text
human command
-> deterministic direct-argv parser
-> checked-in native policy
-> bounded native executor
-> captured output
-> receipt and private event readback
```

The policy is
`md-os/kernel/interaction/native_command_policy.json`. Filesystem commands
start inside `md-os/`, and `cd` cannot leave that boundary. The implementation
does not use Bash evaluation and refuses pipes, redirection, command
substitution, control characters, unsupported `ls` options, and paths outside
`md-os/`.

This is Cortex-style model bypass, with a stronger MD-OS execution boundary.
It is available only to the human operator input channel. A successful native
process and captured output are recorded honestly as executor readback; the
content does not become independently verified truth merely because the
process exited successfully.

## What A Natural-Language Turn Does

```text
input
-> typed InputEvent
-> ephemeral `codex exec`
-> read-only sandbox
-> JSON Schema proposal
-> visible commitment gate
-> optional one-time human approval
-> registered module command
-> executor readback
-> explicit verification status
```

The Console never executes a native command string generated by Codex.
The Codex-compatible output schema constrains the response shape; MD-OS then
performs a second deterministic validation of lane/action relationships and
resolves every requested command against the generated module registry.

## Input Channels

The first GUI exposes three source classes:

| Channel | Authority | Meaning |
| --- | --- | --- |
| Human intent | operator | may approve a pending proposal |
| Agent proposal | advisory | may propose, cannot approve |
| Sensor observation | evidentiary | supplies evidence, cannot approve |

These are not separate GUIs. They are separate typed sources entering the same
executive loop.

## Current Limits

- one ephemeral Codex session per turn;
- deterministic, model-free execution for the declared native read-only
  command policy;
- no cloud agent team scheduler;
- no recursive agent spawning;
- private natural-language command history by default;
- no complete input/response transcript unless `--save-chat` is used;
- only preauthorized native-policy commands or module commands with a
  registered structured argument contract are eligible for execution;
- successful execution is reported as `unverified` until a
  connector-specific sensor and verifier are integrated;
- local prototype only, not a production remote service.

See
[`INTERACTIVE_EXECUTIVE_RUNTIME_MODEL.md`](../md-os/kb/INTERACTIVE_EXECUTIVE_RUNTIME_MODEL.md)
for the architectural model.
