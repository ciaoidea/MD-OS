# Agentic Core Model

The agentic core is the compact, stable operating self-model of MD-OS
(Artificial Prefrontal Cortex) v5.0.

It is not a claim of consciousness, sentience, or demonstrated autonomous
general intelligence. It is a bounded runtime orientation artifact: identity,
mission, invariants, limits, bootstrap order, memory policy, action policy,
connector policy, recovery policy, continuity criteria, objectives, ethics,
operating principles, non-claims, and compaction policy materialized into a
small file that a host runtime can load before expanding large project
histories.

Canonical correlation:
- `docs/ARCHITECTURE.md` defines the current human-facing cognitive-agent
  status, role boundaries, bounded autonomy envelope, end-to-end transaction,
  evidence levels, and maturity gaps.
- `ME.md` defines the root self-description.
- `md-os/kb/AGENT_IDENTITY.md` defines the identity vocabulary.
- `md-os/kb/AGENTIC_OPERATIONAL_RELEASE_MODEL.md` defines the release id,
  semantic-epistemic profile, path migration status, knowledge import binding,
  and release language policy.
- `md-os/kb/RELEASE_VERSION_NAMING_MODEL.md` defines the unified identity name,
  compact release-based agentic identity version, and package semver distinction.
- `md-os/kb/ARTIFICIAL_PREFRONTAL_CORTEX_OS_MODEL.md` defines the PFC-as-OS
  metaphor and the composition of small agentic processes.
- `md-os/kb/SELF_RELEASE_EVOLUTION_MODEL.md` defines explicit version jumps,
  migration plans, compatibility policy, gates, release readback, and rollback.
- `md-os/kb/COGNITIVE_BOOTSTRAP.md` defines the host/runtime framing.
- `md-os/kb/SEMANTIC_OPERATIONAL_NETWORK_MODEL.md` defines the required
  semantic, epistemic, operational, and readback cohesion for coherent action.
- `md-os/kb/SEMANTIC_KNOWLEDGE_GRAPH_MODEL.md` defines whole-Markdown-node
  semantic profiling, concept relation, and compact health readback.
- `md-os/kb/SEMANTIC_NEURAL_OVERLAY_MODEL.md` defines the semantic-runtime,
  task-completion, and Dynamic Virtual LLM framing.
- `md-os/kb/CONCEPTUAL_COLD_BOOT_SUMMARY_MODEL.md` defines generated
  conceptual boot orientation.
- `md-os/kb/AGENTIC_OPERATIONAL_CONTROL_ARCHITECTURE.md` and
  `md-os/kb/AGENTIC_OPERATION_MODEL.md` define the operating control stack for
  intent, state, policy, execution, verification, ledger, and replay.
- `md-os/kb/SYSTEM_OPERATING_CYCLE_MODEL.md` defines the bounded run-once
  operating cycle.
- `md-os/kb/WARM_START_MODEL.md` defines optional volatile working-context
  transfer after stable boot.
- `md-os/kb/OPERATIONS.md` defines healthy operation.
- `md-os/kb/MCP_BOUNDARY_TERMINOLOGY_MODEL.md` distinguishes the `md-os/`
  operating boundary path from the external Model Context Protocol and from
  connectors.
- `md-os/kb/PERMISSION_MODEL.md` defines capability and risk discipline.
- `md-os/kb/ARCHIVE_COMPACTION_MODEL.md` defines non-destructive memory
  compaction.
- `md-os/kb/RUNTIME_DISCIPLINE_MODEL.md` defines the maturity target for a
  disciplined runtime.
- `md-os/kb/MASTER_CLOSURE_DISCIPLINE_MODEL.md` defines domain-neutral master
  closure discipline for complex tasks, separating artifact progress, method
  progress, and closure progress.
- `md-os/kb/SCIENTIFIC_VALIDATION_METHOD_MODEL.md` defines the domain-neutral
  scientific validation gate for research, derivation, validation, and
  manuscript work.
- `docs/FILESYSTEM_CONTRACT.md` defines file roles and publication discipline.
